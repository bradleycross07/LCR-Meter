# firmware

STM32CubeIDE project for the LCR meter, targeting the NUCLEO-G071RB micro-controller.

## Toolchain

Everyone should use the same version, otherwise CubeMX regenerates different files and
pull requests fill up with unnecessary noise.

| Tool                       | Version                |
| -------------------------- | ---------------------- |
| STM32CubeIDE               | 2.2.0 (build 29186)    |
| STM32CubeMX                | 6.18                   |
| STM32Cube FW_G0 package    | V1.6.3                 |

STM32CubeIDE and STM32CubeMX are seperate now, so download & install them from the website at two different places.

[STM32CubeIDE](https://www.st.com/en/development-tools/stm32cubeide.html#section-get-software-table)
[STM32CubeMX](https://www.st.com/en/development-tools/stm32cubemx.html#section-get-software-table)

## Getting started

1. First, make a folder anywhere on your desktop name it something like "Electronics-Project" (it's better without spaces).
2. Open the `Terminal` then change directory into the newly created folder it could be something like `cd ~/Desktop/Electronics-Project`
3. Run this in the terminal (copy and paste) - `git clone https://github.com/bradleycross07/LCR-Meter.git` 
4. It'll make a new folder you can check this in your terminal right now by just typing `ls` (meaning list) and then run `cd LCR-Meter` (pressing `Tab` after `cd` automatically detects `LCR-Meter`) making it easy. And for peace of mind run `git pull` to make sure it's up to date anyways.
5. In STM32CubeIDE: File → Open Projects from File System... and select the
   `firmware/LCR-Meter/` folder inside `Electronics-Project/LCR-Meter`. It is opened in place; nothing is copied into
   your workspace. Keep your workspace folder outside the repository.
6. Build with **Project → Build Project**, then run or debug on the Nucleo
   board over USB.

To change pins, clocks or peripherals: open `firmware/LCR-Meter/LCR-Meter.ioc`
in standalone STM32CubeMX, make the change, click **GENERATE CODE**, then
in CubeIDE right-click the project press F5 on your keyboard.

## Proposed Layout

```
firmware/
└── LCR-Meter/                 the STM32CubeIDE project
    ├── LCR-Meter.ioc          CubeMX configuration (pins, clocks, peripherals)
    ├── STM32G071RBTX_FLASH.ld linker script
    ├── Core/
    │   ├── Inc/               headers (CubeMX-generated + our modules)
    │   ├── Src/               sources (CubeMX-generated + our modules)
    │   └── Startup/           startup assembly file
    └── Drivers/               HAL + CMSIS, generated by CubeMX (committed)
```

Our own code goes in `Core/Src` and `Core/Inc`, one `.c`/`.h` pair per module.

## Rules for CubeMX-generated code (copied from Dave's 'Getting Started' book)

- Only edit generated files **between** `/* USER CODE BEGIN */` and
  `/* USER CODE END */` comments. Anything outside them is overwritten when the
  `.ioc` is regenerated.
- Keep `main.c` minimal: call `app_init()` and `app_run()` from the user-code
  sections and put everything else in our modules.
- Don't reconfigure SysTick, because HAL uses it as its 1 ms time base. Use a
  spare timer (e.g. TIM6/TIM7) for our own timing.
- If you change the `.ioc`, say so in the pull request, and commit the
  regenerated files in the same PR.

## Clock

Set SYSCLK to 64 MHz (that's the board's maximum) in STM32CubeMX, it'll set everything else to 64 MHz. 

## Pin assignments

Record every pin here once it is fixed in the `.ioc`. Pins are still decided once the PCB is fully made.

| Pin        | Function               | Notes                                        |
| ---------- | ---------------------- | -------------------------------------------- |
| PA2 / PA3  | USART2 TX / RX         | Nucleo virtual COM port (debug output)       |
| PA5        | `LED_GREEN`            | Nucleo user LED (also usable by SPI1 / DAC)  |
| PA13 / PA14| SWDIO / SWCLK          | Debugger — **never reassign**                |
| PC13       | User button (B1)       | Nucleo blue button                           |
| PC14 / PC15| LSE 32.768 kHz crystal | On the Nucleo board                          |
| PF0        | MCO input              | 8 MHz clock from the ST-LINK                 |

## Coding conventions

- C11 (CubeIDE compiles with `-std=gnu11`).
- Fixed-width integer types (`uint32_t` etc.) from `<stdint.h>`.
- No magic numbers: use named `#define`s or `const`s.
- Use `snprintf`, never `sprintf`.
- Variables shared with interrupt handlers must be `volatile`.
- Module-private functions and globals are `static`.
- Every public function gets a short comment in its header explaining what it
  does, its parameters and its return value.
