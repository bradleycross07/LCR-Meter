# firmware

STM32CubeIDE project for the LCR meter, targeting the **NUCLEO-G071RB**
(STM32G071RB, Arm Cortex-M0+).

> Status: the CubeMX project is set up with the Nucleo's default peripherals
> (LED, user button, virtual COM port) and a 64 MHz clock. No application code
> yet.

## Toolchain

Everyone should use the **same versions**, otherwise CubeMX regenerates files
differently and pull requests fill up with noise.

| Tool                       | Version                |
| -------------------------- | ---------------------- |
| STM32CubeIDE               | 2.2.0 (build 29186)    |
| STM32CubeMX                | 6.18                   |
| STM32Cube FW_G0 package    | V1.6.3                 |

Since STM32CubeIDE 2.0, CubeMX is **no longer built into CubeIDE**: install
both. The project is pinned to FW_G0 V1.6.3 (*"Use latest available"* is
unticked in Project Manager), so don't upgrade it without agreeing as a group.

## Getting started

1. Clone the repository.
2. In STM32CubeIDE: **File → Open Projects from File System…** and select the
   `firmware/LCR-Meter/` folder. It is opened in place; nothing is copied into
   your workspace. Keep your workspace folder outside the repository.
3. Build with **Project → Build Project**, then run or debug on the Nucleo
   board over USB.

To change pins, clocks or peripherals: open `firmware/LCR-Meter/LCR-Meter.ioc`
in **standalone STM32CubeMX**, make the change, click **GENERATE CODE**, then
in CubeIDE right-click the project and **Refresh** (F5). CubeIDE doesn't notice
regenerated files on its own.

The board's virtual COM port (USART2) is used for debug output. Any serial
terminal works (CubeIDE's built-in terminal, PuTTY, CoolTerm, `screen`, etc.).

## Layout

```
firmware/
└── LCR-Meter/                 the STM32CubeIDE project
    ├── LCR-Meter.ioc          CubeMX configuration (pins, clocks, peripherals)
    ├── STM32G071RBTX_FLASH.ld linker script
    ├── Core/
    │   ├── Inc/               headers (CubeMX-generated + our modules)
    │   ├── Src/               sources (CubeMX-generated + our modules)
    │   └── Startup/           startup assembly file
    ├── Drivers/               HAL + CMSIS, generated by CubeMX (committed)
    └── tests/                 (planned) host-side unit tests for the maths
```

Our own code (planned) is split into modules, each a `.c`/`.h` pair in
`Core/Src` and `Core/Inc`:

| Module       | Responsibility                                              |
| ------------ | ----------------------------------------------------------- |
| `app`        | Top-level state machine; called from `main.c`               |
| `ad9833`     | SPI driver for the AD9833 signal generator                  |
| `lcd`        | 16×2 LCD driver                                             |
| `buttons`    | Mode / Hold buttons, with debouncing                        |
| `measure`    | Timer-triggered ADC sampling into buffers via DMA           |
| `impedance`  | Amplitude/phase extraction and R, C, L calculation          |
| `range`      | Test-frequency and range selection                          |
| `si_format`  | Formatting values with SI prefixes for the LCD              |

`impedance`, `range` and `si_format` should not depend on HAL, so that they
can be unit-tested on a PC.

## Rules for CubeMX-generated code

- In **Project Manager → Code Generator**, tick *"Generate peripheral
  initialization as a pair of '.c/.h' files per peripheral"* and choose
  *"Copy only the necessary library files"*.
- Only edit generated files **between** `/* USER CODE BEGIN */` and
  `/* USER CODE END */` comments. Anything outside them is overwritten when the
  `.ioc` is regenerated.
- Keep `main.c` minimal: call `app_init()` and `app_run()` from the user-code
  sections and put everything else in our modules.
- Don't reconfigure SysTick, because HAL uses it as its 1 ms time base. Use a
  spare timer (e.g. TIM6/TIM7) for our own timing.
- If you change the `.ioc`, say so in the pull request, and commit the
  regenerated files in the same PR.

## Clock

SYSCLK and HCLK = **64 MHz** (the G071's maximum), from the internal 16 MHz
HSI oscillator through the PLL (÷1, ×8, ÷2). AHB and APB prescalers are ÷1.

## Pin assignments

Record every pin here once it is fixed in the `.ioc`. Pins for the AD9833,
LCD, buttons and ADC inputs are still to be agreed with the hardware leader.

| Pin        | Function               | Notes                                        |
| ---------- | ---------------------- | -------------------------------------------- |
| PA2 / PA3  | USART2 TX / RX         | Nucleo virtual COM port (debug output)       |
| PA5        | `LED_GREEN`            | Nucleo user LED (also usable by SPI1 / DAC)  |
| PA13 / PA14| SWDIO / SWCLK          | Debugger — **never reassign**                |
| PC13       | User button (B1)       | Nucleo blue button                           |
| PC14 / PC15| LSE 32.768 kHz crystal | On the Nucleo board                          |
| PF0        | MCO input              | 8 MHz clock from the ST-LINK                 |

## Coding conventions

- C11 (CubeIDE compiles with `-std=gnu11`).
- Fixed-width integer types (`uint32_t` etc.) from `<stdint.h>`.
- No magic numbers: use named `#define`s or `const`s.
- Use `snprintf`, never `sprintf`.
- Variables shared with interrupt handlers must be `volatile`.
- Module-private functions and globals are `static`.
- Every public function gets a short comment in its header explaining what it
  does, its parameters and its return value.
